# What We Learned (`OpenMinion 0.1.24`)

1. **Typed `output_type` on `Handoff` peers avoids string-compaction truncation:** OpenMinion's `BrainRunner` compacts string fields in tool results to 1,200 characters (`outputs.data.output`), which truncates multi-finding JSON strings returned by untyped `Handoff` agents. Declaring `output_type=SolidityAuditResult` and `output_type=ReconBundleResult` keeps structured dictionaries intact in `outputs`.
2. **`subagent()` vs `Handoff()` runtime ownership:** `openminion.subagent()` binds the child to the parent's `APIRuntime`, which triggers `RuntimeError: Temporary tool registration in a cross-thread shared-runtime handoff would deadlock` if invoked inside a `Handoff` tool during `coordinator.run()`. Separating peer `APIRuntime` instances for `Handoff` targets while running `subagent()` directly on the main thread lets both patterns operate reliably.
3. **Explicit `default_channel="console"` and `thread_id` propagation:** Fresh `OpenMinionConfig` agent profiles without `default_channel="console"` fail with `inbound authenticity denied (reason=invalid_channel, mode=warn)`, and multi-turn `Agent.run()` calls require passing `thread_id=result.thread_id` to continue the same conversation thread.
4. **Zero-cost local OpenAI-compatible server preserves full runtime fidelity:** Running an in-process `/v1/chat/completions` server exercises OpenMinion's real `OpenAIProvider`, `LLMCTL`, `GatewayService`, `BrainRunner`, policy engine, and SQLite persistence without monkeypatching or paid API keys, while remaining 1-env-var switchable to `cortensor` or `openai`.
