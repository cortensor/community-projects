# OpenMinion `0.1.24` Building Blocks Tested

This document records the exact empirical results of building and testing **Cortensor Router Doctor** (`cortensor-router-doctor`) on **`openminion==0.1.24`** (with `sophiagraph==0.0.12`, `pydantic==2.14.4`, Python `3.13`).

## Summary Matrix (10 Building Blocks)

| # | OpenMinion `0.1.24` Building Block | Status | What Worked | What Broke / Gotchas | Workaround Implemented |
|---|---|---|---|---|---|
| 1 | **`APIRuntime.from_config(...)` & Isolated Config** | Works with required config flags | Clean SQLite isolation via `home_root`, `data_root`, `StorageConfig`, `RuntimeConfig`, `enabled_plugins=[]`. | Leaving `AgentProfileConfig.default_channel=""` triggers `invalid_channel` errors; default `enabled_plugins=["validate"]` and `reactions_enabled=True` pull extra machinery. | Always set `default_channel="console"`, `enabled_channels=["console"]`, `enabled_plugins=[]`, `reactions_enabled=False`, `telemetry_enabled=False` in [`agent.py`](src/cortensor_router_doctor/agent.py). |
| 2 | **Custom `@tool` Decorator & Risk Metadata** | Works cleanly | `@tool(min_scope="READ_ONLY", idempotent=True)` and `@tool(min_scope="WRITE_SAFE", dangerous=True, idempotent=False)` auto-generate Pydantic v2 `args_model`, `ToolDecl`, and `ToolExposureProfile`. | Passing no `tools=[...]` to `Agent` exposes ~179 built-in tools to small models, causing tool confusion and token bloat. | Explicitly pass `tools=[probe_cortensor_router, evaluate_sla_policy, apply_router_quarantine]` to `Agent` so `allowed_tools` strictly allowlists only our 3 domain tools. |
| 3 | **Ollama Provider Adapter (`OllamaProvider`)** | Broken under defaults; works with `"native"` | Fast local native tool calling (~1.25s/call verified with `qwen2.5:1.5b` at `127.0.0.1:11434`) once `tool_call_strategy="native"` is set. | **BUG-1**: `OllamaProviderConfig.tool_call_strategy` defaults to `"fallback"` (`providers.py:85`), which omits `payload["tools"]` (`adapter.py:269`) AND disables fallback parsing for normal tools (`adapter.py:323`: `fallback_enabled=bool(request.tools and schema_only_submit_output)`), silently dropping all tool calls! Also `adapter.py:333` has a missing `f` prefix, printing literal `ollama pull {model}`. | Explicitly configure `OllamaProviderConfig(tool_call_strategy="native")` in `build_isolated_config()`. Verified in `test_bug1_ollama_default_fallback_drops_tools_and_has_missing_fstring`. |
| 4 | **Cortensor Portal (`openai`) & Cortensor Router (`cortensor`) Adapters** | Works with tuned timeouts | `CortensorProvider` supports `/api/v2/completions`, session pools, and retry/backoff; `OpenAIProvider` works cleanly with Cortensor Portal `/v1/chat/completions`. | Default `RuntimeConfig.chat_turn_timeout_seconds` is `90.0`s, which is far shorter than `CortensorProviderConfig.timeout_seconds=420`s and `precommit_timeout_seconds=300`s—causing turns to time out mid-inference on decentralized PoI queues. | Set `chat_turn_timeout_seconds=480.0` for both `cortensor-portal` and `cortensor-router` presets. |
| 5 | **Declarative `Agent.run_stream(...)` & `output_type=BaseModel`** | Works with explicit schema prompt | `on_delta` receives streaming progress events; `_coerce_output()` recovers JSON objects even if wrapped in prose and validates via Pydantic v2. | `Agent(output_type=RouterAuditReport)` does **not** inject `RouterAuditReport.model_json_schema()` into the LLM system prompt automatically, causing small models to guess field names and fail `AgentOutputValidationError`. | Explicitly embed `RouterAuditReport.model_json_schema()` in `build_audit_instructions()` and cross-check outputs with `verify_report_against_evidence()`. |
| 6 | **Approval-Gated `ActionPolicy` (`approval_callback`)** | Works cleanly | Under `ActionPolicyConfig(mode="auto", default_action="require_confirm", allow_read_only_without_prompt=True)`, `READ_ONLY` tools run uninterrupted while `dangerous=True, idempotent=False` tools pause and invoke `approval_callback(tool_name, args, approval_id)`. | Returning `False` denies execution cleanly, but models occasionally still hallucinate `quarantine_applied=True` in their final summary unless explicitly verified. | Record every approval decision in `AuditExecutionResult.approval_events` and enforce `verify_report_against_evidence()` against actual tool execution. |
| 7 | **Low-Level `APIRuntime.submit_turn()` & `RuntimeTurnHandle`** | Partial — stream timeout broken (**Issue #872**) | `submit_turn(payload={..., "deliver": False})` returns a `RuntimeTurnHandle` with `stream()`, `resolve_approval(approval_id=..., decision="allow_once"|"deny")`, `cancel()`, and `result(timeout_s=...)` -> `TurnResponse`. | **BUG-2** ([openminion/openminion#872](https://github.com/openminion/openminion/issues/872)): `TurnHandle._iter_chunks()` (`turn_handle.py:258`) calls `self._stream_cv.wait(timeout=timeout_s)` and ignores its `False` return value inside `while True:`, causing `handle.stream(timeout_s=...)` and `handle.subscribe(timeout_s=...)` to hang forever! | Consume `handle.stream()` in a daemon watcher thread bounded by `handle.result(timeout_s=...)` and call `handle.cancel()` on `TimeoutError` (`run_audit_via_submit_turn()`). |
| 8 | **Durable Memory Store (`rt.runtime_memory_assembly.service`)** | Works cleanly | `MemoryService.write_record(scope="agent:router-doctor", record_type="fact", ...)` and `list(ListQueryOptions(...))` persist and query structured JSON audit facts reliably in SQLite across turns. | Internal `_store` access vs public service APIs are mixed inside `MemoryMerger`, making rollback semantics subtle. | Encapsulate writes and reads behind clean `record_audit_incident()` and `list_audit_incidents()` helpers in [`memory_ops.py`](src/cortensor_router_doctor/memory_ops.py). |
| 9 | **Memory Portability (`MemoryBundleSnapshot` & `MemoryMerger`)** | Broken atomicity & allowlist (**Issue #873**) | `export_bundle_snapshot()`, `write_bundle_snapshot()`, and `read_bundle_snapshot()` create SHA-256 verified `.tar.gz` bundles cleanly. | **BUG-3 & BUG-4** ([openminion/openminion#873](https://github.com/openminion/openminion/issues/873)): `MemoryMerger._import_direct_mode` (`merger.py:341-417`) writes non-conflicting records directly to `_store.put()` before encountering a later conflict under `conflict_mode="error"`, returning `applied=False` with partial writes persisted! Furthermore, `MemoryMerger` completely ignores `options.namespace_allowlist`. | Implemented `validate_bundle_preflight()` and `import_audit_bundle_atomic()` in [`memory_ops.py`](src/cortensor_router_doctor/memory_ops.py) to enforce namespace allowlists and all-or-nothing conflict validation before calling `import_bundle_snapshot()`. |
| 10 | **Bounded `subagent()` & `Handoff` Delegation** | Works with two critical workarounds | `subagent(parent, ..., timeout_seconds=60)` creates isolated `SubagentRunContext` lineage without sharing hidden reasoning or owning the parent runtime. | **BUG-5**: `Handoff.resolved_description()` (`handoff.py:158`) crashes with `IndexError` if `target.instructions` is whitespace-only (`"   "`). **BUG-6**: Passing the same `@tool` callable to both parent and child collides in the shared `ToolRegistry` during nested handoff runs (`agent.py:196-238`). | Always set explicit non-empty `description=` on `Handoff`, and pass tool **name strings** (`["probe_cortensor_router", "evaluate_sla_policy"]`) to `subagent(...)` (`build_forensics_handoff()`). |
