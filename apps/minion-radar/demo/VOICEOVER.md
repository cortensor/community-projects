# Minion Radar voice-over (about 2 minutes)

Speak over `demo/minion-radar-demo.mp4`. The picture is a paced playback of a real Cortensor Portal run on 22 Nov 2026 in Africa/Lagos (WAT). The live command took 4 minutes 10 seconds; the quiet model wait is cut and labelled. Do not show or read any API key. The key stays in the ignored `.env` file.

**Opening, while the command is typed (about 20 seconds):**

This is Minion Radar, an Open Minion agent for Cortensor Hackathon 5. It tells a builder what changed in a repo since they last looked. I am running it live on the Open Minion GitHub repo, using the Cortensor Portal oss 20b model.

**When the snapshot line appears (about 15 seconds):**

There is the snapshot tool. That is live GitHub data, not a fixture. It found one new release and eight new issues. Next the hosted model writes a short builder brief, then the agent saves a checkpoint. That checkpoint is a local write, so Open Minion asks for approval. Film mode auto approves it so the step is visible on screen.

**When the trimmed-wait caption appears (about 15 seconds):**

The hosted model took four minutes and four seconds on this run. The tools themselves were quick. Almost all of the wait is model latency, so the video jumps to the moment the brief came back.

**When the approval line and brief appear (about 50 to 70 seconds):**

And there is the approval step. The next run will only show items newer than this checkpoint. Here is the brief, generated by the model, not the fallback. The headline is Open Minion 0.1.24, which adds multimodal input and stronger provider retry behavior. The release link keeps the official GitHub tag, including the leading v. The issues to watch are number 446, a Postgres migration conflict, and number 717, where provider retry ignores Retry After on a 429. Both of those are real open issues. The actions follow from that: deploy 0.1.24, check the retry logic, and fix the shared alembic version.

**Close (about 15 seconds):**

That is a full real model run with the Open Minion SDK: tools, structured output, a session, and an approved memory write. Setup is in the README. Thanks for watching.
