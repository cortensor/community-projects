### Honest limitation

The SDK-native `Agent.run` path against the Pollinations free tier is unreliable for **structured** work, and reliable enough for **prose** work. Usually a turn fails with HTTP 402 (`1 reply every 45 seconds per IP`): one native turn fires several consecutive model calls, the first consumes the quota, and the SDK's hardcoded 300 ms retry backoff cannot wait out a 45 s window. When a turn survives the rate limit, the free model still free-forms its JSON — for classify it invents its own field names (`issue_id` / `status` / `classification`) and a same-session follow-up returns all nulls — because the SDK has no `response_format` / `json_object` support. The classify step therefore stays on the direct HTTP client (one call per step, paced ≥45 s, tool_calls + `response_format` `json_object`). The **draft** step does run through `Agent.run` (`output_type=None`, raw reply parsed at the app level — the reply arrives as `triage: {"answer": ...}` and the `answer` field is the draft); see the `sdk_native_draft` probe. A failed SDK draft turn falls back to the direct draft, so triage still completes. See `docs/WHAT_WE_LEARNED.md` §4.
